# Activity-log result lines render one selectable control per line, with the category color as a side stripe

ADR 0012 colored the result tags by stacking a colored TextBlock under a transparent-foreground selection TextBox. That drifts once a result line wraps: the TextBox theme style outranks font inheritance (the same mechanism the cell style already patches for Foreground), so the layers lay out on different metrics — and even with the fonts pinned, two engines rendering the same string can be proven aligned only per device, per locale, per installed font, which is exactly the matrix this multilingual tool cannot pin down. Decision: each line of the row's `ActivityLogResultProjection` renders as its own read-only TextBox, so the selection rectangles come from the same engine that draws the glyphs and drift is impossible by construction. The category color moves off the text: each line carries a colored stripe at its left edge, outside the selectable text, using Paul Tol's high-contrast triad for in-cell bar↔bar scan (OCR `#004488`, 原文 `#DDAA33`, 译文 `#BB5566`); these stripe hexes may differ from Video.xaml preview badge Foregrounds and from ADR 0012's text-era palette. The bracketed tag text stays inside the TextBox, so copied text still equals displayed text, tags included. Untagged lines (detection-miss, action rows) get no stripe; the match-miss line borrows the source stripe, mirroring its tag borrowing. The stripe variant was picked over whole-line foreground, background tint, and plain text in a throwaway HTML prototype (`prototype/activity-log-result-variants` branch), judged in a full-window mock with real columns, colors, repeat dimming, wrap, and selection interaction.

**Considered Options**: keep the stack and mirror FontFamily/FontSize the way Foreground already is (fixes the known systematic drift, but font-fallback chains, trailing-space wrapping, and DPI rounding stay unprovable, and the forever "everything but color, applied symmetrically" contract survives); RichTextBox per cell (the one native control with colored runs and native selection, but a FlowDocument per recycled row — ADR 0012's rejection stands); AvalonEdit (a new third-party dependency, excluded); a custom FormattedText-drawn control (single engine, but hand-rolled mouse selection and an accessibility regression).

**Consequences**: drag-selection no longer crosses result lines inside one cell — each line selects alone, half-line partial copies (the case ADR 0011 preserved) still work inside a line, and whole-row Ctrl+C / context-menu copies are unchanged; a cell hosts up to three TextBoxes instead of the TextBlock+TextBox pair, the same cost class under the stripped no-inner-scroller template — re-verify scroll smoothness against the recycled-cell work; `ActivityLogResultTextBlock`, the `LogResultSelectionTextBox` style, and the "color only, never weight/family/size" editing ban are retired; tag text plus stripe gives color-blind operators a double encoding; UI automation no longer reports every cell's text twice. Supersedes ADR 0012, which remains the record of the stacked-layers era and its calibration warnings.
