# Activity-log result tags are colored by a TextBlock stacked under the selection TextBox

*Superseded by ADR 0016 — one selectable control per result line, with the category color as a side stripe.*

The result column's three lines get bracketed result tags — `[OCR]`, `[原文]`, `[译文]` (localized per language) — with each tag in its own color: OCR blue `#315EA8` and source green `#287A4B` (the same pair the recognition-preview badges in Video.xaml already use), translation purple `#8250DF`; content text stays the default foreground. WPF forces a trade here: a TextBox renders plain text only (one foreground, one weight), a TextBlock formats runs but has no selection at all — and ADR 0011's per-cell selection and copy-on-select must keep working, including partial in-line selections such as copying half a subtitle line. Decision: the TextBox stays exactly as the selection layer with its Foreground set transparent, and a TextBlock underneath renders the same string with the tag runs colored. Both layers are composed from the same typed segments (tag text plus quoted content, per locale), so copied text equals displayed text, tags included; the projection emits segments instead of parsing localized prefixes, keeping the session on resource keys per ADR 0008. The colored layer may differ from the selection layer in **color only**: weight, font family, and size are forbidden — bold tags would shift glyph advances between the layers and silently misalign selection rectangles from the visible text. Repeat-row dimming therefore moved from Foreground `#888888` to Opacity so both layers dim together.

**Considered Options**: a plain TextBlock with colored, bold runs (richest look, but zero selection in the result column — partially superseding ADR 0011 — and partial copies become impossible); one TextBox per result line (keeps in-line selection, but whole-line coloring, no bold either, and cross-line drag-selection within the cell is lost); RichTextBox or AvalonEdit per cell (a FlowDocument per recycled row, or a third-party editor dependency, for one log column).

**Consequences**: the read-only caret is invisible (keyboard selection in log cells was already unreachable — cells are not tab stops; mouse flows are unaffected); the selection highlight draws as the standard blue over the colored glyphs; any future change to font, padding, or line format must be applied to both layers symmetrically, and adding bold to the colored layer is the one edit that breaks alignment silently — do not do it; UI automation exposes the cell text twice (TextBlock plus TextBox); a residual sub-pixel inset of the TextBox may need a one-time margin calibration.
