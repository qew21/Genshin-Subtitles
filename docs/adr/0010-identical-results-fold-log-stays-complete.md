# Identical results fold while the activity log stays complete

A pipeline run that concludes the same recognition result as its pair is already showing — no text found, or the same matched subtitle — keeps the current display and does not replay voice; the run still happens and is still recorded, as a repeat row. Rows are never dropped at write time: repeat detection marks the row, and a default-on settings checkbox hides repeat rows in the activity log window only. Turning the checkbox off reveals every run; it does not switch the fold itself off — the overlay never re-applies an identical result. Force refresh is an operator action: it re-applies, replays voice, and its row is never a repeat. A match miss (OCR read text, the pack had no entry) no longer blanks the region — the previous subtitle stays until the region empties or a new match lands, because a partial line mid-typewriter cannot match yet. Detection-miss repeats are marked like any other repeat; match-miss rows differ by OCR text and repeat-mark only when their result is the same. No settle gate was added: frames may still drift above threshold and re-run OCR (identical frames are absorbed by the OCR hash cache); the choice favored zero added subtitle latency over saved recomputation. ApplyPairResult no longer writes pipeline rows on its own — CompleteOcr writes the queue-run row, and the force path carries a force flag that both bypasses the fold and writes the operator row — so one recognition has exactly one writer and the double-write seam is closed structurally, not by a guard.

**Considered Options**: suppress repeats at write time (breaks the complete-record promise, irreversible); require consecutive stable ticks or a settle window before enqueueing OCR (adds subtitle latency, slows typewriter updates); a per-pair cooldown after OCR (never stops the first run); keep ApplyPairResult writing with a same-recognition guard (cannot tell the seam's double call from a genuine identical run).

**Consequences**: last-result state is per pair, replaced by the next different result and reset when the region goes empty-stable, so the same text reappearing later is a fresh row; duplicated voice replays during drift re-triggers disappear with the fold; drift beyond the hash's tolerance still costs real OCR compute; the dead legacy branch of ApplyRecognizedText (pair-less, not forced, not dark-screen) is removed; the log window re-projects when the checkbox changes.
